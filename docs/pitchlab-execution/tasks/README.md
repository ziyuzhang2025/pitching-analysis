# Task lifecycle

Statuses: OUTLINE, READY, ACTIVE, BLOCKED, COMPLETE. Only [active.md](active.md) selects the current task.

Before activation: check milestone dependencies, inspect target code, replace broad outcomes with exact interface/test steps, and identify owner and authorized actions. Later outlines do not authorize implementation.

At completion: record changes and revision, verification command/environment/result, both system and capability gates, residual limits and next eligible task. Keep the file at its stable path.

A software task may be system-verified while capability assessment is pending. Record this explicitly; do not mark the milestone fully defended.

Task paths use repository-relative code locations. Documentation links are relative to their files. Use [task-template.md](task-template.md).
